# X26 切磋主动技选择与对战可用性返修

2026-10-30。来自用户反馈：手动切磋会把所有必中主动技依次放完，法宝 / 徒手与闪避构筑缺少选择价值；出招面板的技能说明大量截成「…」；心魔还没选出招方式就亮出血条；对战中缺少主动认输。

本任务同时处理**战斗规则、手动选择成本、面板信息完整性、血条显示时机、认输闭环**。不重做素材，不顺手重构其他战斗系统。

## 1. 验收目标

1. 串门 / 隔空切磋每场每方最多主动选择 **3 次主动技**；达到上限后，手动面板、AI 清单与引擎合法动作都不再提供主动技。
2. 切磋里普通主动技恢复闪避判定，只有明确的招牌杀招保留必中；miss 也消耗该招与一次主动技额度。
3. 出招卡片完整显示技能说明，不用省略号藏掉效果；面板高度随内容调整，超出最大高度才滚动。
4. 心魔 / 切磋在出招方式尚未选定时不显示血条，正式开演才显示。
5. 心魔、串门切磋、隔空切磋在对战中可认输；二次确认后按本方负场结算。联机认输必须让双方得到同一场 `forfeit` 结局，不能按掉线处理。
6. 自动、AI、手动三种模式都有覆盖；真实切磋规则（65% 伤害、单发 30% 封顶）进入平衡模拟，不再只拿托管全伤害局判断手动体验。

## 2. 主动技额度（只影响切磋）

- 新常量 `SPAR_ACTIVE_LIMIT = 3`。沿用现有 `sparRules` 判断：串门 / 隔空切磋启用；心魔、历练、渡劫保持原规则。
- `Side` 记录本场剩余主动技额度。每次**真正选择并执行** `action.kind === 'skill'` 扣 1，包括增益、控制、回血、聚气；被闪避也扣。
- 每门主动技原有「一场一次」继续生效，3 次是额外的全场预算。
- 鲸派气功的自动释放不再次扣额度；聚气那一手已经扣过。
- 凭空生花追加的一手仍按正常合法动作处理；若继续放主动技，再扣 1，额度不足则不能放。
- `BattleView.you` 新增可选 `skillUsesLeft?: number`，只在切磋局填；`legalActions`、`legalize`、`autoController`、AI / 手动共用同一上限。
- 手动面板标题显示「主动技剩 X 次」；为 0 时主动技按钮不出现在清单里，不能靠 curl / 对端报文绕过。

## 3. 切磋命中分层

### 3.1 保留必中的招牌招

| 招式 | 保留位置 |
| --- | --- |
| 蓝鲸现世 `blue-whale` | 直接伤害 |
| 五指拳心剑 `finger-sword` | 直接伤害、穿护体照旧 |
| 无头鬼影 `headless-shadow` | 直接伤害、取首级照旧 |
| 鲸派气功 `tide-cannon` | 蓄力后的释放 |
| 前有古人 `ancients` | 下一次出手前的补击 |
| 鬼敲门 `ghost-knock` | 记号触发的一击 |

深渊领域、瞬影仍只强化**普通攻击**，不额外让其他主动技必中。

### 3.2 恢复普通命中判定的主动技

- 伤害 / 控制：狮子吼、鲸歌、鲸吞、魂牵梦绕、降龙十八掌、送友风、万我大手印、鬼手、鬼血。
- 指定对方的效果：墨汁喷射、鬼画；吃苦吃亏对对方泡泡 / 魂影 / 咬一口的效果。
- 这些招在切磋里用与普通攻击一致的 `dodgeRate(foe)`；对方睡着 / 入梦 / 飘着时仍必中。
- 闪避后：不掉血、不回血、不附加控制 / 封印 / 送走 / 后劲，不消耗魂影、泡泡或护身印；该主动技与全场额度照常消耗。
- 吃苦吃亏闪避时仍可清掉自己的墨汁（自身效果），但吃不到对方任何东西。
- 自增益招不作命中判定：凭空生花、万我、逆流护身印、深渊领域、瞬影、聚气起手。
- 事件复用现有 `decide` + `dodge`：出手动作与飞行物照播，对方播闪避；miss 不再补一个带 0 伤害的 `skill` 事件。非切磋事件序列与规则不变。
- 抽取规则要固定：切磋里每个需要判定的主动技固定抽一次命中随机数，必中时也照抽，避免换招无意义地挪动后续随机序列。

### 3.3 面板口径

`SKILL_EFFECT` 不能继续把上述普通主动技写成「必中」。切磋面板按当前规则显示完整效果；保留必中的招牌招明确写「必中」，普通招不写或写「可闪避」。非切磋面板口径不变。

## 4. 出招面板完整说明

- 去掉 `.action .effect` 的单行 `nowrap + ellipsis`；说明允许自然换行，长单词 / 英文 id 可断行。
- 卡片不再固定 34px 高：名称保持单行，效果区按实际文字撑高，同一网格行对齐。
- `panelHeight` 不能再按固定卡片高度硬算；以页面 `contentHeight()` 实测为准校正，最大高度仍为 420，超过后滚动。
- `chooseAction` 增加可选标题参数，供「主动技剩 X 次」使用；现有调用保持兼容。
- 新增认输入口时不得把效果区重新挤成省略号。

## 5. 血条显示时机

- `openArenaWindow` 增加可选初始可见性配置与 `setVisible(visible)`，默认保持旧行为，避免影响历练等调用方。
- 心魔与切磋选择出招方式时使用 `initiallyVisible: false`；选完方式、第一场时间线 / 第一段逐手演出正式开始前才 `setVisible(true)`。
- 页面尚未加载完时调用 `setVisible` 要记录目标状态，load 完成后按目标状态显示，不能抢先亮一下。
- 关闭方式面板、取消应战、收摊仍走原窗口组清理，不留下空血条。

## 6. 对战中认输

### 6.1 范围与入口

- 覆盖：心魔试炼（自动 / AI / 手动）、串门逐手切磋、隔空逐手切磋（自动 / AI / 手动）。
- 不覆盖：渡劫（没有对手）、历练（已有独立战斗与奖励流程）。
- 在现有对战菜单的「快进」旁提供「认输」，手动出招面板也提供次要「认输」入口；两处调用同一个处理函数。
- 必须二次确认，默认选择「继续打」；确认等待期间暂停当前出招倒计时，恢复后不能凭空吞掉一手。

### 6.2 结局与结算

- `BattleEvent.end.reason` 新增 `'forfeit'`；`winner` 为认输方的对方，气血采用双方都已确认到的最新事件值。
- 本地心魔：立刻停止等待 AI / 手动选择与当前演出，按负场走现有 `trialDone`、日记与收摊；自动局也不能继续播完预先算出的胜负。
- 联机：扩展现有逐手报文，支持 `forfeit: true` 与成功应答里的认输通知；沿用现有身份、令牌、序号校验。
- 发起方认输后，双方 `done` 都返回带同一个 `forfeit end` 的事件数组，按正常胜负记账；不能回 `null`，不能走进「切磋断了」。
- 认输请求序号过期、重复、已结束：幂等或按现有 `late` 处理，不能重复记账。
- 认输报文未送达 / 对端未确认：沿用现有掉线不记账规则，不能一端记赢另一端记输。
- 原有 `dispose()`、掉线、回家、取消切磋语义不变，不能借认输路径静默覆盖错误。

## 10. 实施结果（2026-10-30）

### 10.1 落地内容

- **引擎**（`battle.ts`）：`BATTLE_VERSION = 9`、`SPAR_ACTIVE_LIMIT = 3`、`you.skillUsesLeft`、`end.reason` 新增 `forfeit`；切磋里 15 门需判定的主动技恢复 `dodgeRate`，招牌招（蓝鲸现世 / 五指拳心剑 / 无头鬼影）与延迟触发（鲸派气功释放 / 前有古人 / 鬼敲门）保留必中；miss 仍扣招与额度、不触发后续效果。
- **面板**（`action-panel-window.ts`）：效果说明自然换行，卡片按内容撑高，页面 `contentHeight()` 实测高度、上限 420；`chooseAction` 支持可选标题。
- **血条**（`arena-window.ts`）：`initiallyVisible` + `setVisible()`，load 前只记目标状态；心魔与切磋在选完出招方式 / 正式开演后才亮。
- **认输**：
  - 菜单「修炼/认输」+ 手动面板末尾的「认输」，都走同一份二次确认（默认「继续打」）。
  - 心魔自动局：立刻停演，`won` 按负场算，日记带「认输」，不会把预先算好的胜负记进去。
  - 心魔 AI / 手动：`LiveBattle.forfeit()` 中止等待与演出，`done` 返回带 `forfeit end` 的正常事件。
  - 串门 / 隔空逐手局：`LiveVersus.forfeit()` 走 `/v1/spar/turn`、`/v1/duel/turn` 的 `forfeit: true` 报文，两边拿到同一个 `forfeit end`；请求没送到 / 对端没确认仍回 `null`（掉线、双方都不记账）；已结束后重复 / 迟到按幂等或 `late` 处理。
  - 范围外：渡劫（没有对手）、历练（独立结算）、旧对端不带逐手协议的全自动切磋。
- **平衡模拟**：`scripts/dev/battle-sim.mjs --spar` 用真实切磋参数（65% 伤害、单发 30% 封顶、`fairSparPair`）对比托管与「主动伤害技优先」。

### 10.2 平衡数据（每项 300 场，甲手动主动技优先 / 乙托管）

| 境界 | 随机配招：托管 | 随机配招：主动技优先 |
| --- | --- | --- |
| 筑基中期（stage 10） | 0.480 | 0.493 |
| 合体初期（stage 25） | 0.493 | 0.417 |

- 单招最高（stage 10 主动技优先）：鲸歌 0.570、狮子吼 0.563、送友风 0.560；招牌必中招反而更低（蓝鲸现世 0.460、五指拳心剑 0.437、无头鬼影 0.393），说明「先把所有必中招放完」不再是免费优势。
- stage 25 主动技优先整体低于托管（0.417 vs 0.493）：3 次额度 + 恢复闪避后，无脑优先主动技会亏节奏。
- 存量偏高项不在本次范围：万我 0.723（stage 10）、凭空生花 0.640 / 逆流护身印 0.630（被动与自增益，不受 X26 命中分层影响），鲸派气功 0.313 偏低；本次未改 PvE / 被动数值。

### 10.3 偏差与限制

- **认输确认用独立小面板**（自动 / AI 局会登记为当前出招面板；手动局不借正在等的那块）。因此计划里「确认期间暂停出招倒计时」未实现：手动局点菜单认输时，手上这一手的 20 秒倒计时照跑，可能超时按后备出招；但不会多吞一手，也不会取消这一手。
- **双方同时认输**时各记各的负场（不做平局裁决），不会出现一端记赢一端记输。
- 认输后演出立即停止，不再补演胜利 / 倒地收场，窗口按原有 1 秒收摊；整场时间线里的 `forfeit end` 仍能正常排出胜利 / 倒地与「认输」台词（供未来整场回放）。
- 未做真机核验：Electron 多窗口的认输面板位置、血条时机、双机联机认输都只跑了自动化测试；未提交、未 push。
