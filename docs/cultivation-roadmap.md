- **对战者**：
  ```ts
  interface Fighter {
    name: string; // 显示用
    hp: number; // 气血上限（开打时满血）
    power: number; // 灵力
    agility: number; // 身法
    speed: number; // 遁速
    weapons: WeaponId[];
    skills: SkillId[];
  }
  ```
- **接口**：`fight(a: Fighter, b: Fighter, seed: string, controllers?: [Controller, Controller]): BattleEvent[]`。
  - **两路随机数**（为以后的手动对战留口子）：决策用 `sha256(seed + ':decide')`，结算用 `sha256(seed + ':resolve')`，各喂一个小 PRNG（自己写几十行，比如 xoshiro128\*\* 或 sfc32，不引依赖）。换了出招者，结算序列不受影响。
  - **出招者 `Controller`**：轮到某方出手时，引擎问它 `decide(view): Action`，`Action` 是「用某件法宝攻击 / 空手攻击 / 用某个主动招式」。现在只实现 `autoController(decideRng)`：可用的「凭空生花」在气血低于一半时必用；其余没用过的主动招式每次 25% 用；否则在自有法宝里随机挑一件，20% 空手。
  - **出手顺序**：时间轴式。每方下次出手时刻 = 上次 + `100 / (遁速 + 10)`（鲸尾 ×1.2）。初始时刻 = 一个间隔 × 结算随机数 U(0.8, 1.2)。同一时刻 a 先。
  - **结算**（起点）：
    - 闪避率 = min(35%, 身法 × 1.5% + 化鸽遁 8%)；必中的不判闪避。
    - 伤害 = 法宝区间随机 + ⌊灵力 / 2⌋，空手 3–6 + ⌊灵力 / 2⌋；会心一击 ×2；泡泡护体挡一半（向下取整）。
    - 连击：一次攻击打中后，按 min(30%, 身法 × 1%) + 加成 再打一次，同一回合最多连击 2 次。
    - 反击：第六感见上表；远程法宝（水枪）和灵兽不会被反击。
  - **收场**：一方气血 ≤ 0（假死遁生效时留 1）即结束；出手满 30 次还没分出来，按剩余气血比例判，相同则遁速高的赢，再相同 a 赢。
  - **事件**：`BattleEvent` 是可辨识联合，每个事件带 `actor`（0 / 1）、`kind`，以及事件后的 `hp: [number, number]`。至少有：`start`、`decide`（记下这次的 `Action`，以后回放手动对战用）、`hit`（含 `weapon`、`damage`、`crit`、`blocked`）、`dodge`、`combo`、`counter`、`skill`（含 `skill`、`damage?`、`heal?`）、`beast`、`skip`（被定住跳过）、`play-dead`、`end`（含 `winner`、`reason: 'ko' | 'timeout'`）。
- **渡劫**：`tribulate(f: Fighter, strikes: number, stage: number, seed: string): BattleEvent[]`。N 道天雷依次劈下，第 i 道伤害 = 某个随境界涨的基数（自己定，按 §平衡 调）。能用上的：闪避（按一半闪避率算）、泡泡护体、假死遁；凭空生花在两道雷之间、气血低于一半时用。熬过全部雷 = 成功。事件 `kind` 用 `strike`、`end` 等，和 `fight` 共用类型。
- **心魔**：`shadowOf(f: Fighter): Fighter`，属性 ×0.9（向下取整，最低 1），法宝招式相同，名字「心魔」。
- **能力上限**：`statCap(stage: number): { hp, power, agility, speed }`，给 X5 校验名帖用，按 X1 的成长规则算出该境界可能的最大值（再留 10% 余量）。X1 之前先按 X1 的规则写死公式，X1 里要有一个测试保证成长结果不超过它。

**解说 `src/app/battle-lines.ts`**（配单测）：`lineOf(event, names, rng): string | null`。每种事件、每件法宝、每个招式配 2–3 句模板，例如「{a}掏出水枪滋过去，-{d}」「{b}化成一只鸽子躲开了」。每句 ≤ 40 字，不调模型。`decide`、`start` 这类不需要台词的事件返回 null。

**平衡**：

- `scripts/dev/battle-sim.mjs`：随机生成成千上万对角色对打，打印胜率表（按境界差、按每件法宝和每个招式）。用 `node --experimental-strip-types` 直接 import `src/app/battle.ts`（参照 `scripts/test-register.mjs` 的做法）。
- `battle.test.ts` 里放确定性的平衡断言（固定种子 0..N，N 取让测试 3 秒内跑完的量），目标：
  - 同一境界、随机配招的两只，a 的胜率在 40%–60%；
  - 任一法宝或招式，持有方对不持有方（其余随机）的胜率不超过 65%；
  - 高一个小境界（按 X1 的成长规则）约 60%，高一个大境界约 85%（各给 ±10% 容差）；
  - 心魔：本体对 `shadowOf(本体)` 胜率 55%–70%；
  - 渡劫：同境界随机配招，不吃丹约 65%、吃丹（气血 ×1.2）约 80%（±10%）。
- 同境界的属性按 X1 的成长规则生成。X0 先写一个测试用的 `fighterAt(stage, rng)` 放在测试工具里，X1 再换成正式的。

**测试**（除平衡外）：同种子同结果、不同种子不同结果；换出招者不改变结算随机序列（比如两边都换成「永远空手」，结算序列照旧可复现）；每种招式至少一个用例确实触发；假死遁只救一次；30 次出手封顶；事件里的 `hp` 和实际一致、不为负。

**模型调用**：0。

3. **命中时刻对方才反应**：飞行物到达的那一刻画命中特效，对方的受击 / 泡泡 / 闪避按这个时刻起播。命中时刻是程序自己算出来的（出手时刻 + 飞行时间），不再靠估素材里的打击时刻。

**时间线**（`timeline` 仍是纯函数，只多算「什么时候放、什么时候到」，不碰坐标）：

- 一格的出手：动作在 `cursor` 起播（倍速照旧 `rateFor(动作, SLOT_MS)`）；出手时刻 `release = cursor + round(releaseMs / rate)`；这一格第 k 段伤害（第一段 k = 0）的飞行物在 `release + k × BEAT_MS` 放出，第 i 个（多发的）再加 `i × 间隔`；**第一个**到达的时刻就是这段伤害的命中时刻 `impact`。
- `Step` 加一个 `shot` 字段（谁放的、飞行物种类、轨迹、飞行时间、个数、间隔、命中贴图、`miss`），执行器到点交给新的一只手 `ShowSides.shoot`。
- 对方的反应对准 `impact`，扣掉反应素材自己的前摇（原速时刻 ÷ 反应素材倍速）：`战斗-受击` 后仰在 0.5s、`战斗-闪避` 侧身在 0.6s、`招式-化鸽遁` 隐身在 1.0s、`招式-泡泡护体` 泡泡挨撞在 1.4s。反应素材倍速固定按 `REACT_ANIM_MS` 算（不再随延迟变）。
- **闪避**：飞行物 `miss: true`——飞过目标继续往前、淡出，不画命中特效；对方的闪避 / 化鸽遁对准它掠过的时刻。**挡下**（`blocked`）：照样画命中特效（打在泡泡上），对方播泡泡护体。
- 结算台词（「-15」那种）挪到这段伤害的 `impact` 那一刻出；没有飞行物的事件（`skip`、回血等）台词照旧。
- 第六感：反击方先挨（上面的受击），挨完再播 `招式-第六感`（照旧「先挨后反」），手刀按这段素材的出手时刻飞回去，原攻击方在手刀到达时受击。
- `HIT_AT_MS`、`REACT_WINDUP_MS`、`reactDelayOf` 和法宝 / 招式整段素材的时长条目改完就没用了，删掉（测试跟着改）。

**X7 落地情况**（2026-10-26，第一、二、三步都做了，真机验证过）：

- **开发方式**：dsh headless 写了第一版（`battle-show.ts` 的出手表与 `Shot`、`fx-window.ts`、`features.ts` 三处接线、`/app/fx`、删掉图鉴里的 `anim`），中途两次因模型服务报错（tool call has no name）断掉；第三步的专属素材到齐后，主会话接手重写了时间线与特效页面，测试全部重写。
- **衔接口径**（用户要求「从出招到道具、特效到受击衔接丝滑」）：所有素材首尾都是标准站姿，所以只要同一只宠物的一段动画不被下一段从中间切断就是无缝的。时间线给两只各记「忙到几点」：出手类（主攻、灵兽、连拳、第六感的反劈）排在自己上一段播完之后，下一格等两只都回到站姿再隔 150ms；受击必须对准命中不能往后挪，所以上一段反应还没播完就不另起（只画命中特效、掉血、出台词），只有假死遁照样起播。`battle-show.test.ts`「衔接」那条拿真引擎扫遍境界（空手、自动出招、渡劫）断言没有一段被切断。

- **五指拳心剑**（剑道仙级杀招）：原著里的打法是**双手合十 → 右手捏拳、高举过顶 → 拳心射出一道剑光**（B 站两个剪辑里能看到：旁白「右手捏拳，高举在头顶正上方」，以及画面上打的原文「他高高立在虚空的右拳拳心，忽然射出一道剑光……剑光之快，匪夷所思」）。玩法落成**拳心藏剑**：必中，剑光穿体，护体挡不住。不做「血量阈值斩杀」那种追加——**「拳心」是拳心，不是心口**。

**引擎改动点**（`battle.ts`）：

1. `Side` 加 `mirror: number`，`makeSide` 给 0。
2. `attack()`：判完闪避、进水母分身之前插一段 `if (!sure && foe.mirror > 0) { foe.mirror -= 1; events.push({ actor: (self ^ 1) as 0 | 1, kind: 'mirror', hp: hpPair(sides[0], sides[1]) }); continue; }`——复用现成的 `sure`（必中 / 回旋末段 / 睡着），魂影和闪避共用同一套「必中穿不过去」的规则。

4. `applyDamage(target, raw, opts?: { pierce?: boolean })`：`pierce` 时不算 `blocked`、不扣 `bubbles`、不打折。现有调用全部不传，行为不变。

### X10 演出期间占住宠物（不再插播随机活动）

X9 真机时发现、2026-10-26 修掉：心魔试炼、渡劫、切磋演到一半，宠物会插播堆雪人、吃糖葫芦这类随机活动。

- **根因**：演出用 `/anim` 播的每一段都是「播一次」，播完渲染端的 `handleEnded` 就接回随机链（`playIdle`）。两段演出动画之间的空当（对手出手、等下一格）就会掷一次骰子，抽到随机活动、转身，甚至自己走开。工作状态和余额这两样自动来源的表现也会插进来。
- **改法**：不加新接口，用现成的占用锁（`/lock`，issue #122 给第三方联动演出做的）。三处有自家宠物画面的演出（`runTrial`、`runTribulation`、`runHostSparShow`）在 `run()` 之前 `holdPet(steps)` 拿锁，演完 `releasePet(CLOSE_HOLD_MS)` 放锁。退出时立刻放；客人那一侧的转播没有画面，不拿锁。
  - 锁住时渲染端不推进动画链，每段播完就停在最后一帧。素材都从标准站姿开始、回到标准站姿结束，所以两段之间看上去是站着等。
  - 锁的时长 = 时间线长度 + `SHOW_LOCK_SPARE_MS`（30 秒），不超过 `LOCK_MAX_TTL_MS`。上一场刚演完、锁还没放就开下一场时，续上同一把锁（续不上就重新拿）。
  - 持锁期间，应用自己的请求统一带上 `?lock=`（`petRequest`），所以提醒、串门这些照常能说话、播动画；第三方插件按占用锁的约定被挡住。
  - 用户点了或拖了宠物，渲染端会强制释放锁。之后带锁的请求回 `lock-lost`，`petRequest` 就不带锁重发一次，这一场剩下的部分照没锁的老样子演完，不跟用户抢。
- **测试**：`features.test.ts` 加了两条。第一条：心魔试炼开场动画之前先拿锁，演出期间的 `/anim`、`/broadcast` 都带锁，演完 3 秒放锁。这条是回归测试，临时撤掉 `holdPet` 时会失败。第二条：锁被撤掉后不带锁重发、后面不再带锁、演完不再放锁。全量 **1307/1307**。

### X11 台词里名字后面的「的」不重复

X10 真机时发现（2026-10-26）：宠物名字以「的」结尾（用户的宠物叫「吃白饭的」）时，对战台词会出现「吃白饭的的灵兽扑出偷袭」「吃白饭的的烟花在心魔脚边炸开」。

**现状**：`battle-lines.ts` 的模板里有十几句写成 `{a}的…` / `{b}的…`（水枪、扑克牌、毽子、雪球、鸡毛掸子、陀螺、托盘、烟花、灵兽、水母分身、魂牵梦绕、掸子挠痒、弹弓、穿护体……），`fill()` 只是把 `{a}` / `{b}` 原样换成名字。X9 遇到时只改写了 `mirror` 那两句的措辞，没有根治。

**改法**：

- 在 `fill()` 里先处理 `{a}的` / `{b}的`，再处理单独的 `{a}` / `{b}`：名字已经以「的」结尾就不再补「的」（「吃白饭的」+「的灵兽」→「吃白饭的灵兽」），其余照旧（「小蓝」→「小蓝的灵兽」）。
- 只认「占位符紧跟一个『的』」这一种写法。名字中间的「的」、模板里别处的「的」都不动，也不对整句做全局的「的的 → 的」替换（那样会误伤名字里本来就有的叠字）。
- 模板本身的措辞不改，X9 改过的 `mirror` 两句保持现状。
- 心魔、客人（切磋时对方家的宠物）也走同一个 `fill()`，所以对方名字以「的」结尾时一样生效。

**测试**（`battle-lines.test.ts`）：

- 名字用「吃白饭的」：所有带 `{a}的` / `{b}的` 的模板都填一遍（主角、对手两个位置都要覆盖），结果里都不出现「的的」。用 `lineOf` 加一个能挑到每一句的 `rng` 覆盖到每一句，或者其他能证明「每一句都覆盖到」的办法。
- 名字用「小蓝」：照旧是「小蓝的…」（回归，不能把正常名字后面的「的」吃掉）。
- 名字中间带「的」（比如「我的猫」）、但不以「的」结尾：照旧补「的」。
- 现有的长度断言（每句 ≤ 40 字，名字按 12 字算）照旧全过。

**验收**：prettier --check、typecheck、lint、`npm test` 全过；改动只在 `battle-lines.ts` 和 `battle-lines.test.ts`。演出层不用改；真机由主会话做。

### X12 切磋时客人那边也演全套

用户 2026-10-26 提出：去别人家做客时切磋，客人自己的屏幕上也要看到这一场，不能只转播台词。这一条推翻 §X5「演出」里「客人那边只转播台词」的口径，也推翻 §X7、§X10 里「客人那一侧没有画面」的说法。

**现状**：

- `startGuestSpar` 已经按同一份事件序列排时间线、跑 `BattleShow`，但两边的 `play`、`shoot`、`arena` 都是空操作，台词全走 `showRelay`，转播到自家宠物的气泡里。

**改法**：

1. **台词种子**（`visit.ts`）：新增 `sparLineRng(guestNonce, hostNonce): () => number`，种子取 `${guestNonce}:${hostNonce}:lines`。实现复用 `battle.ts` 的 `rngFrom`（目前没导出，导出它，不要另写一个 PRNG）。主人家 `runHostSparShow` 和客人 `startGuestSpar` 的 `timeline(...)` 都改用它。心魔试炼、渡劫照旧用 `Math.random`。
2. **换边**（`battle-show.ts`）：新增纯函数 `swapSides(steps: Step[]): Step[]`。每一步的 `who` 0↔1、`hp` 两项对调，其余字段（`at`、`anim`、`from`、`rate`、`line`、`shot`、`closing`）原样保留。`Shot` 的字段都相对出手方，不用改。返回新数组，不改入参。
   - 时间线必须先按引擎序号算（主人家是 0 号），名字和招式表的顺序都照引擎来，然后再换边。不能为了让自家变成 0 号，直接把名字或招式表反过来传：台词、闪避动画（化鸽遁）都按序号查，反过来传就对不上了。
3. **客人这边的演出**（`startGuestSpar`）：接法照 `runHostSparShow`，差别如下。
   - **对手窗口**：`openGuestWindow(electron, <本机 /app/guest>, `${owner} 家的 ${pet}`, homePet.box, () => undefined, { scale: 1, tight: true })`。配色用默认粉色，和主人家屏幕对称：两边都是自家原色、对方粉色。开演前 `preload(SHOW_ANIMS)`。

### X13 心魔收益随间隔恢复（不封顶）

**来由**：用户反馈修为来源太单一，第二期规划（`cultivation-adventure-design.md`）拍板「心魔的收益不封顶」（§8 第 2 条）。原来当天只有第 1 场有收益。但心魔能快进，直接放开的话，连点「心魔试炼」「快进」一小时能刷约 8 000，是挂一整天的 25 倍多。所以改成收益随间隔恢复（设计 §7.3 的办法 B）。

**改法**（`cultivation.ts` 的 `trialDone`）：

- **不封顶**：场次和总量都不限。`today.trial` 改成「今天打了几场」。
- **按间隔恢复**：收益随离上一场的间隔线性恢复，隔满 `TRIAL_RECOVER_MS`（10 分钟）给满额，赢 +30、输 +10。不满 10 分钟时，修为和掉落概率（满额 30%）都按比例打折。修为先乘后除、向下取整：一分钟一场正好 +3，不到 20 秒一场一点没有。不管多久打一场，一小时最多约 +180。
- **存档**：上一场的时刻存进存档的 `trialAt`（zod `.default(0)`，旧档当没打过），重启不清零。时钟往回拨过（`now` 早于上一场）就按间隔 0 算。
- **冒泡**：没恢复满时多一条事件 `{ kind: 'trial-tired', minutes }`，排在 `xp` 前面。`features.ts` 的 `onCultivation` 冒泡「心魔还没缓过来，这一场收益打了折；再过 N 分钟打才是满额～」，不进日记。
- **圆满时**：修为本来就不涨，但掉落照样按间隔打折，所以「没缓过来」照样说。

**测试**（`cultivation.test.ts`、`features.test.ts`）：

- 同一天隔一小时连打三场，都满额进账。

### X14 演完马上收摊、心魔窗口不泄漏

**来由**：

- X11 记的心魔窗口泄漏，在 X13 放开场次以后更容易碰到。
- 用户反馈（2026-10-27）：打完以后，对战画面结算要快一点。

**现状**（`features.ts` 的 `runTrial`）：

```text
最后一步（收场）→ 等 LINE_MS（2.4 秒，让结果台词显示完）→ run() 结束 → battle = null
→ 记账、奖励冒泡 → await compose（赛后感言，要等模型，几秒到十几秒）
→ say(感言) → refreshMenu → closeTrial(CLOSE_HOLD_MS = 3 秒)
```

- **慢**：心魔窗口、擂台、特效层要等模型编完感言再停 3 秒才关。菜单在 `run()` 结束后还挂着「快进」（点了没反应），也要等感言回来才换回「心魔试炼」。主人家那边的切磋（`runHostSparShow`）也是先 `await compose` 再 `closeSparWindows`，一样慢。
- **泄漏**：`run()` 一结束 `battle` 就清零，`runTrial` 的拦截条件放行。这时再点一场（菜单被别的事刷新过，就会出现「心魔试炼」），新的一场会把 `trialWindows` 覆盖掉。第一场的三扇窗再也没人关；第一场稍后的 `closeTrial(CLOSE_HOLD_MS)` 反而关掉了第二场的窗口。测试里的表现是 `features.test.ts` 偶尔跑完不退出：心魔窗口那两个 interval 一直挂着。

**改法**（只改 `features.ts`，演出 `battle-show.ts` 不动）：

1. **演完就收摊，不等赛后感言**：
   - `runTrial`：`run()` 结束后的顺序改成：`battle = null`、放锁、记账与奖励冒泡、记日记，**马上 `refreshMenu()`**，然后关这一场的窗口（停 `CLOSE_HOLD_MS`）。这些都在 `await compose` 之前。
   - 赛后感言照旧调一次模型，回来再说（`anim: false`）。
   - `runHostSparShow` 同样处理：`closeSparWindows(windows, CLOSE_HOLD_MS)` 和 `refreshMenu()` 挪到 `await compose` 之前。
   - 客人那一侧（`runGuestSparShow`）本来就不等模型，不用改。
2. **`CLOSE_HOLD_MS` 从 3 秒改成 1 秒**，注释跟着改。
   - 理由：`run()` 结束时，结果台词已经显示了 `LINE_MS`（2.4 秒）；收场动画按 `CLOSE_MS`（3 秒）配的倍速，只剩约 0.6 秒，再停 1 秒正好播完。
   - 用到它的放锁、渡劫特效层、切磋窗口、客人那边退回半透明都跟着变快，口径一致。
3. **每一场的窗口归这一场**：
   - `runTrial` 把这一场的三扇窗留在局部变量里，收摊时只关自己那一组。`trialWindows` 只在它还指着这一组时才清零。
   - 新开一场时，上一场还没关完的那组立刻关（0 毫秒）。
   - 敲门、退出等现有调用 `closeTrial(0)` 的地方，照旧立刻关当前那组。
   - 关窗的接口怎么改（加参数，还是换成和切磋一样的 `Set`），选简单的。
4. **过时的感言不说**：赛后感言回来时，如果已经开了下一场（`battle` 不是 null），这一句就不说了，免得插进下一场的台词里。
5. 渡劫（`runTribulation`）的特效层本来就在 `await compose` 之前关，只跟着第 2 条变快，不用别的改动。

**不变的**：
- 记账口径、奖励冒泡和日记都不变。
- 每场仍只多 1 次模型调用（赛后感言）。
- 快进照旧直接跳到收场。

**测试**（`features.test.ts`，旧断言不能弱化；时长相关的断言跟着新值改，并在回报里写明）：

- **回归（泄漏）**：让 `compose` 挂着不返回。第一场快进打完以后马上开第二场：
  - 第一场的心魔窗口、擂台、特效层都被销毁；
  - 第二场的三扇窗在第一场原来的收摊时刻之后还开着；
  - 第二场打完、放开 `compose` 以后，所有窗口都销毁。
  - 临时撤掉第 3 条的改动，这条测试要失败。
- **收摊不等模型**：`compose` 挂着不返回时：
  - 一场打完 `CLOSE_HOLD_MS` 以后，三扇窗都已销毁；
  - 菜单里已经是「心魔试炼」，不是「快进」；
  - 修为、日记已经记上；
  - 放开 `compose` 以后，感言照常说出来。
  - 主人家的切磋同样测「窗口不等感言就关」。
- **过时的感言**：第一场的感言在第二场开演以后才回来，这一句不出现在气泡里。
- **放锁**：X10 那条「演完 3 秒放锁」改成按 `CLOSE_HOLD_MS` 断言。

**验收**：

### X15 不串门也能切磋（隔空切磋）

**现状**：

- 切磋只在串门进行中出现：菜单是 `串门/和客人切磋`、`串门/找主人家的宠物切磋`，协议 `/v1/spar` 要带进门时发的令牌。
- 客人那一侧（`startGuestSpar`，X12）已经是在自家屏幕上开对手窗口、擂台、特效层，自己演完整场。隔空切磋两边都照这个演。

**协议**（`visit.ts`，接待端口上新增两条；安全口径同 `/v1/knock`：只收私网来源、带 Origin 一律拒、请求体有上限、名字和台词过 `cleanText`）：

1. 挑战方发 `POST /v1/duel { owner, pet, id, pub, ts, sig, mode, card, commit }`。
   - 签名内容新增 `duelMessage`（`visit-identity.ts`）：`['dsh-pet/duel/v1', 应战方 id, 地址:端口, ts, owner, pet, commit].join('\n')`。承诺签在里面，别人改不了；前缀和敲门不同，敲门的签名挪不过来用。
   - 验签、时间戳新鲜度照敲门那套。没有 id 或验不过回 `bad-sig`：不接匿名挑战，奖励和邻居簿都靠 id。
   - 同一时间只挂一个挑战；同一地址 `KNOCK_COOLDOWN_MS` 内只能挑一次（和敲门各算各的）。
2. 应战方挂着等主人答复，最多 `DUEL_WAIT_MS`（30 秒）：
   - 应战：回 `{ ok: true, card, nonce, token, id, pub, sig }`。`sig` 签 `duelAcceptMessage`：`['dsh-pet/duel-accept/v1', 挑战方 id, 地址:端口, token].join('\n')`，口径同进门应答。挑战方验不过就当对方没应。
   - 不应战、30 秒没人点：回 `declined` / `timeout`，**不记输赢**。
   - 其余原因照 `/v1/spar`：`off`、`busy`、`version`、`unsupported-mode`、`bad-card`。
3. 挑战方发 `POST /v1/duel/reveal { token, nonce, line }`。对不上或 30 秒没来，按挑战方认输（同 X5）。
4. 两边各算 `sparFight(应战方, 挑战方, 挑战方随机数, 应战方随机数)`：应战方当 0 号，和串门切磋里主人家当 0 号同一口径。台词种子照用 `sparLineRng`。

- 旧版本的对端没有 `/v1/duel`（404），映射成 `old-host`，挑战方说「对方的桌宠还不会隔空切磋」。连不上就说没连上。
- `BATTLE_VERSION` 不变。

**应战方**（`features.ts` 接线）：

### X17 逐手出招的底子 + 心魔试炼

**来由**：用户 2026-10-27 提出：不要只能开打前整场算好，要能让 AI 一手一手地挑法宝和招式，也能自己手动出招；整场自动的保留。拍板：

- 三种出招方式：**自动**（现在这样，开打前整场算好）、**AI 出招**（每轮到自家宠物出手，问设置页配的模型）、**手动出招**（每轮到自家宠物出手，主人自己点）；
- 每次开打前选，不放进设置页；
- AI 出招时，模型想说才说一句（比如「先用陀螺晕住它！」），不想说就不说；
- 范围：心魔试炼（X17）、历练（X18）、串门切磋和隔空切磋（X19）。渡劫只挨雷，没有出招可选，不动。

**引擎**（`battle.ts`）：照设计 §4.16「重放到缺决策处」的走法，`fight` 保持同步、纯函数，不改成异步：

- 新增 `fightUntilDecision(a, b, seed, sources)`：`sources` 是每一边的出招来源，`'auto'`（`autoController`，吃决策随机数）或一串已经定好的 `Action`。轮到某一边、它那串已经用完时，停下来返回 `{ events, need: { side, view } }`；打完返回 `{ events, need: null }`。外层把这一手补进那一串，**从头再算一遍**（一场几毫秒）。
- 只有一边是 `'auto'` 时，决策随机数只被那一边吃，所以从头重算时它的挑法每次都一样。另一边用定好的那串，不吃决策随机数。
- `legalActions(view): Action[]`：这一手能出什么（自有法宝、空手、没用过的主动招式、还有次数的招）。AI 和手动的选择、X19 收到的对方出手，都要先过它，不合法就当没选。
- 后备挑法 `fallbackAction(view, seed, index)`：AI 超时、答不出合法的招，或者手动没点，就用它。照 `autoController` 的口径，随机数用 `rngFrom(seed + ':fallback:' + index)` 单独一路，**不吃**决策随机数，不然从头重算时对面的挑法会变。
- 每一手照旧记 `decide` 事件。现有的 `fight()` 结果一字不变：全自动的场次不走新函数，`battle-sim.mjs` 的胜率表和现有测试都不动。

**演出**（`battle-show.ts`）：

- 现在是整场事件一次生成时间线。逐手模式改成**一段一段地演**：算到下一个决策点，就把新多出来的那段事件接到时间线后面演，演完停在待机姿势，等这一手定下来。
- **边演边想**：一段一开演，下一手（如果轮到自家）就开始问 AI，不用等动画播完；演完了还没定就停着等，气泡里显示「想一想…」。
- 全自动的场次走原来的整场时间线，不改。

**出招面板**（新窗口，页面走本机服务的 `/app/...`，同 `/app/arena` 的做法）：

- 挂在擂台下面。只在两个时候出现，其余时间关掉：
  - **开打前选方式**：三个按钮「自动 / AI 出招 / 手动」。10 秒不点按自动。
  - **手动出招时轮到自家**：`legalActions` 每一项一个按钮（法宝名、招式名，有次数的标剩几次），带倒计时。20 秒不点就按后备挑法出。
- 面板要能点（不穿透），但不抢焦点：主人正在打字时弹出来，不能把输入框的焦点抢走。
- AI 出招时面板不出现，只在宠物头上显示「想一想…」。

**AI 出招**：

- 每一手发一次模型请求：
  - 系统提示用宠物人设；
  - 正文给双方气血（含上限）、自己的法宝和招式（名字 + 一句效果）、对方的法宝和招式、这场已经用掉的、`legalActions` 编号清单；
  - 要求只回 JSON `{"pick": 编号, "line": "可选，20 字以内"}`。
- 校验 `pick` 在清单里，`line` 过 `cleanText`。解析失败、超时（15 秒）、模型没配好，这一手都按后备挑法出。整场不中断，日志里记一笔。
- `line` 有值时，宠物在出这一手时说出来（`say(..., { anim: false })`），替掉这一手模板解说里自家宠物的那句；没给就照旧。
- **限流**：现在 `ai-provider.ts` 一分钟 12 次的限流会把一场 AI 局卡死（一场自家最多出 15 手）。AI 出招的请求另给一份额度（建议一分钟 30 次），不占、也不挤掉看屏幕和对话的那 12 次。也不排在说话队列（`speaking`）后头：打的时候看屏幕本来就停着。
- 模型没配好时，开打前的三选一里「AI 出招」灰掉。

**心魔试炼接线**（`features.ts`）：

- 菜单还是一项「修炼/心魔试炼」。点了先弹出招面板选方式：
  - 选自动：和现在完全一样；
  - 选 AI 出招或手动：走逐手。
- 菜单不拆成三项：现在菜单正好顶到 20 项的上限，拆了会把邻居挤掉。
- 逐手的心魔照样占锁、开三扇窗（对手、擂台、特效层），收摊时出招面板一起关。退出、有人敲门、`closeTrial` 时面板也关，等着的 AI 请求作废。
- 快进（`修炼/快进`）在逐手模式下的意思是：剩下的手全按后备挑法、立刻算完，演到最后。
- 收益不变：AI 和手动可能比自动打得好，先不另调；真机打几场看胜率再说（设计 §4.16 也记着这一条）。
- 日记照旧，后面加「（AI 出招）」或「（手动）」。

**测试**：

- `battle.test.ts`：
  - `fightUntilDecision` 两边都是 `'auto'` 时，和 `fight()` 的事件逐条一样（固定一批种子）；
  - 一边一串定好的手：每补一手从头算，之前的事件前缀不变，对面的挑法也不变；

### X19 切磋逐手对传（串门切磋 + 隔空切磋）

**难处**：切磋是两台电脑各算同一场，现在靠「两边随机数先承诺后揭示 → 同一个种子 → 整场能复现」。AI 和手动的选择没法复现，所以要**每一手都把出招传给对方**，两边按同一串出手各自从头算。

**谁定方式**：

- 发起的一方（客人点「和主人家的宠物切磋」/ 主人点「和客人切磋」/ 隔空切磋的挑战方）开打前在出招面板里选自家宠物的方式。
- 2026-10-28 改：不管选哪种，一律是**逐手局**，请求 / 邀约里带 `mode: 'live'`，选自动只是自家每手按后备挑法出。用户反馈应战方没得选；能和 `BATTLE_VERSION` 4 对上的对端都已支持逐手局，不用降级。最早是只有选 AI 或手动才走逐手局，选自动整场照旧协议算好。
- 另一方答应以后在自己的出招面板里选自家宠物的方式（自动 / AI / 手动，10 秒不点按自动）；熟人自动应战也弹面板（2026-10-28 改，最早固定按自动）。
- 旧对端发来的全自动局（不带 `mode: 'live'` 的请求或邀约）照旧整场算好，这边不弹面板。
- 两边各管各的宠物：A 的模型或主人只替 A 出招，B 也一样。

**协议**（`visit.ts`；承诺揭示、名帖、版本这些照旧）：

- 揭示之后不再一次算完，改成按出手顺序一手一手来。发 HTTP 的总是客人 / 挑战方那一边：
  - `POST /v1/spar/turn`、`POST /v1/duel/turn`，带 `{ token, index, action? }`；
  - 轮到发请求这一边出手时，带上自己这一手；
  - 轮到对方出手时，这个请求挂着等，对方定了再回 `{ action }`。
- 每一手的时限：出手的一方自己保证 20 秒内给出（AI 15 秒、手动 20 秒，过了都用后备挑法），所以对方总能等到。等的一方 35 秒还没收到，就当**掉线**。
- 收到的出手先过 `legalActions`，不合法也当掉线，不替对方编招：替对方编的话，两边会算出不同的一场。
- 旧版本的对端回 `unsupported-mode`，发起方说「对方的桌宠还不会逐手切磋」，不自动降成全自动。
- X16 推迟了，做 X19 时还没有送友风。以后做 X16 时，逐手局里的送友风按 X16 自己的规则接上（`':farewell'` 那一路随机数两边一样算）。

**记账**：

- 逐手局在**打完时**才记（`sparDone`、`recordSpar`、日记）。全自动局照旧在开打那一步记。
- 掉线了两边都不记，宠物说一句「切磋断了」，收摊。

**测试工具**：`visit-peer.mjs` 的 `host` 和 `duel` 支持逐手局。对面那边按后备挑法出手，加一个参数可以故意不回，用来试掉线。

**测试**：

- `visit.test.ts`：
  - 逐手局两边按同一串出手，算出同一串事件；
  - 对方出了不合法的招、超时，都按掉线处理；
  - 旧对端回 `unsupported-mode`；
  - 全自动局的报文和现在一字不差。
- `features.test.ts`：
  - 串门切磋、隔空切磋各走一场逐手局（自家 AI 或手动，对面自动）；
  - 掉线不记账、窗口全关；
  - 打完才记账。

**验收**：同 X17；真机用 `visit-peer.mjs` 扮对面，串门和隔空各打一场逐手局，再试一次掉线。

### X20 对战再平衡：控制判定、修为拉平、数值重标

**来由**（2026-10-29 用户）：狮子吼、鲸歌、魂牵梦绕、送友风几个控制招是必中的，谁先出手谁赢；切磋里修为差直接压死对方，希望修为最多影响两成胜率或完全不影响；顺带把法宝、招式的数值重新标一遍。

> §X0–X16 里的法宝 / 招式数值是当时的记录；以本节表格和 `battle.ts` 为准。

**控制不再是必中**（`battle.ts`）：

- 四个控制招统一过 `controlLands(self, skill)`：命中率 = 招式基础值 +（施放者灵力 − 目标身法）× 2%，夹在 25%–85%。基础值：狮子吼 60%、鲸歌 75%、魂牵梦绕 55%、送友风 65%。
- 没压住时照样结算伤害（狮子吼、鲸歌、魂牵梦绕、送友风都有伤害），事件带 `resisted: true`，解说走 `RESIST_LINES`（「没被震住」「没被哄睡」这类）。
- **不允许连控**：`Side.controlled` 在控住时置位，那一方下一次真正出手时清掉；处于 `controlled` 时任何控制（招式和法宝的 `skipChance`）都压不上。这样「控住一拍 → 刚醒又被控」的锁链断掉，先手不再等于赢。
- 鲸歌从纯控制改成带伤害：基础 16 + 灵力 × 0.6，另按目标气血 30% 加成；压不住只迟缓。
- 假死遁救回来的人**躺一拍**（`skipCause: 'sham'`），不再白赚一个完整回合；解说加 `skipSham` 一句。

1. **伤害入口收敛**：新增 `dealDamage(self, raw, opts)`，内部先看挨打方 `reversal`，再走 `applyDamage`。现有的主动招式伤害（狮子吼、蓝鲸、鲸歌、鲸吞、魂牵梦绕、五指拳心剑、降龙十八掌、送友风）和 `attack()` 里那一下都改走它；第六感反击、灵兽助阵、渡劫 `strike` 不动。
2. `Side` 加 `reversal: number`（护身还剩几次）、`sealed: null | 'weapon' | 'skill'`（下一次出手不能用法宝 / 招式）、`ancient: boolean`（古人还挂着）；`makeSide` 各自给 0 / null / false。
3. `dealDamage` 里：`target.reversal > 0 && raw > 0` 时，`target.reversal -= 1`，把这一段伤害按 `REVERSAL_SHARE` 算出来（`floor(raw × 0.7)`）打回攻击方，推进 `reverse` 事件，返回「没打到本体」。反弹出来的伤害**不再**判闪避 / 魂影 / 分身 / 替挡 / 反击，也不触发攻击方的 `reversal`（只反一层，防套娃）；护体 / 假死照常走 `applyDamage`。
4. 万我大手印：必中伤害结算后对方还活着就 `foe.sealed = 'weapon'`；`view()` 里把 `sealed` 填进 `you`；对方下一次真正出手时清掉（同 `blind` 的口径，在 `takeAction` 开头清）。
5. 前有古人：施放时 `me.ancient = true`；`takeAction` 开头若 `me.ancient`，先推 `ancient` 事件、对对方 `applyDamage(80)`，再清标记，然后照常出这一手。被控跳过不算「真正出手」，标记一直挂着。
6. 吃苦吃亏：按泡泡 → 魂影 → 咬一口的优先级结算，回血夹在上限内；顺手 `me.blind = 0`。
7. 具名常数摆在 `MYRIAD_MIRRORS` 那一片：`PALM_BASE = 26`、`PALM_HP_SHARE = 0.5`、`REVERSAL_TIMES = 1`、`REVERSAL_SHARE = 0.7`、`ANCIENT_BASE = 80`、`EAT_HEAL = 0.15`、`EAT_MIRROR_HEAL = 0.12`、`EAT_BITE_BASE = 40`。后三个数值是按平衡实测从起点调上来的（见下）。

**解说**（`battle-lines.ts`）：四门的出手句各两句；`reverse` 两句（「逆流一卷，打回去的是你自己」）；`ancient` 两句；`devour` 三种各两句；`sealed` 两句（法宝被攥住）。照现有口吻，总长仍 ≤ 40 字。

- **鬼眼**：原著看穿鬼与幻象，落成**破替身 + 免致盲**——水母分身、万我魂影在鬼眼面前没用，墨汁糊眼也看不见。补上现有招式里没有的「反替身」轴。
